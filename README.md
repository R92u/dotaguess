# Dota Match Guess 2.0

Сайт-игра для игрока Dota 2 с account ID `1524768829`. Каждый день в 00:00 МСК сервер выбирает **два разных матча** из 20 последних. Посетитель изучает составы, статистику и предметы, затем угадывает: победил игрок или проиграл.

## Что изменено

- исправлено отображение предметов: `/constants/items` OpenDota индексируется по полю `id`, а не по текстовому ключу предмета;
- два матча в сутки вместо одного;
- вкладки «Матч 1» и «Матч 2» с отдельными ответами;
- общий лидерборд по количеству правильных ответов;
- обновление лидерборда в реальном времени через Server-Sent Events;
- защита от повторного начисления победы одному браузеру за один матч;
- необязательное PostgreSQL-хранилище для Render;
- автоматическая замена записи текущего дня, созданной старой версией сайта.

## Локальный запуск

Требуется Node.js 20 или новее.

```bash
npm install
cp .env.example .env
node --env-file=.env server.js
```

Откройте `http://localhost:3000`.

Тесты:

```bash
npm test
```

## Обновление существующего сайта на Render

1. Замените файлы проекта содержимым этого архива.
2. Build Command: `npm install`.
3. Start Command: `npm start`.
4. Задайте переменные:
   - `NODE_ENV=production`;
   - `TRUST_PROXY=true`;
   - `APP_SECRET` — длинная случайная строка;
   - `PLAYER_ACCOUNT_ID=1524768829`;
   - `DATABASE_URL` — Internal Database URL из Render Postgres, если нужен постоянный лидерборд.
5. Выполните Manual Deploy с очисткой build cache, если браузер продолжает показывать старую версию.

### Важно для лидерборда на Render

Без `DATABASE_URL` приложение использует JSON-файл в `DATA_DIR`. На обычном Render Web Service файловая система может очищаться при рестарте или новом деплое. Поэтому для постоянного лидерборда используйте один из вариантов:

- Render Postgres и переменную `DATABASE_URL`;
- платный Web Service с Persistent Disk и `DATA_DIR`, указывающим на каталог диска.

При первом подключении к PostgreSQL приложение само создаст таблицу `dota_guess_state`.

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PORT` | порт HTTP-сервера | `3000` |
| `PLAYER_ACCOUNT_ID` | 32-битный Dota account ID | `1524768829` |
| `OPENDOTA_API_KEY` | необязательный ключ OpenDota | пусто |
| `APP_SECRET` | подпись скрытых идентификаторов матчей | тестовое значение |
| `DATA_DIR` | каталог JSON-хранилища | `./data` |
| `DATABASE_URL` | PostgreSQL; при наличии заменяет JSON-хранилище | пусто |
| `TRUST_PROXY` | учитывать `X-Forwarded-For` | `false` |

## Как считается лидерборд

- участник задаёт имя;
- браузер создаёт случайный локальный идентификатор;
- один правильный ответ даёт одну победу;
- повторная отправка ответа с того же браузера за тот же матч не начисляет победу повторно;
- полноценной регистрации пока нет, поэтому очистка данных браузера создаст нового участника.

## Источник данных

Используются OpenDota endpoints:

- `/players/{account_id}/recentMatches`;
- `/players/{account_id}`;
- `/matches/{match_id}`;
- `/constants/heroes`;
- `/constants/items`.

Поля `item_0`–`item_5`, `backpack_0`–`backpack_2` и `item_neutral` содержат числовые ID. Endpoint `/constants/items` возвращает объект, ключи которого являются внутренними названиями предметов, поэтому приложение предварительно строит собственный индекс `ID → предмет`.
